# 45 双核并发共享资源与中断边界

[返回总目录](../../README.md) · ESP32-D0WD / 4 MB Flash / ESP-IDF 6.1。

## 双核竞争与共享状态

ESP32-D0WD的两个核心可真正并行访问变量。即使某个对齐32位读写是单次访问，count++仍由读、加一、写回组成；两个核心同时读到旧值，最后可能只增加一次。

将任务固定到一个核心不会自动消除竞争，另一个核心的系统任务、驱动回调或中断仍可能访问资源。优先队列传值和单一所有者，让一个任务管理一个设备，其他模块通过消息交互。

## 临界区与响应时间

短共享状态可用IDF临界区保护。跨核机制涉及自旋锁，因此不能在临界区内延时、等待队列、访问网络或打印长日志。任务间长期资源访问可用互斥锁，但同样应限制持锁范围。

响应延迟可分为检测、等待中断、排队和处理。轮询周期10ms本身可能带来约10ms检测延迟，提高后端优先级无法消除前端误差。定位时在数据边界放时间戳，逐段分析。

线程安全、可重入、中断安全是不同属性；某函数可以多任务调用，不代表可以从ISR执行。

## 回调到队列的真实例程

本章TWAI工程采用节点API进行单节点自测试。按工程要求将GPIO25与GPIO26短接，开启self-test和loopback，不接真实CAN总线。真实网络必须经过收发器连接CANH/CANL，GPIO不可直接接总线。

接收回调中received_t有自己的8字节数组，驱动填入数据后，xQueueSendFromISR按值复制到队列。回调返回后消费者仍持有有效副本。回调不格式化长日志、不写文件、不使用普通阻塞队列接口。

发送方向采用引用语义：驱动持有frame与buffer指针，因此要等twai_node_transmit_wait_all_done成功才能修改。示例超时后先停止节点再结束循环，避免控制器仍在访问时重用缓冲。

这个对比说明必须读清每个API的内存语义：看起来都在“发数据”，有的立即复制，有的异步借用。

## Flash缓存与IRAM

Flash操作期间缓存可能不可用。要求此时仍可运行的ISR，需要按驱动要求放入允许的内存区域，并检查调用链和数据位置。只给函数加IRAM_ATTR，不保证它调用的格式化代码或访问的常量也安全。

中断中动态分配、浮点重计算和嵌套等待都会扩大延迟。典型方法是中断记录时间与必要状态，发通知，由任务执行复杂计算。高精度时序优先使用硬件定时、DMA和专门外设，不能依赖任务忙等。

## 验收与故障定位

正常回环应接收到对应计数。增加CPU负载后记录延迟和队列满次数，不能把一次回环成功当作真实CAN电气层已经验证。真实总线还需要检查位速率、收发器、终端、共地和节点数量。

当前回调队列满时丢弃该帧，正式系统应增加统计。练习：添加丢帧计数。参考：在ISR中用合适的原子或短临界区更新，任务定期读取；不要为了统计每帧都在ISR打印。

## 完整工程与运行

[源码](../../examples/esp-idf/twai_loopback/main/main.c)，[构建配置](../../examples/esp-idf/twai_loopback/CMakeLists.txt)。先激活IDF 6.1，从手册根目录运行。

Windows PowerShell：

```powershell
Set-Location examples/esp-idf/twai_loopback
idf.py set-target esp32
idf.py build
$port = Read-Host '输入实际串口'
idf.py -p $port flash monitor
```

Linux Bash：

```bash
cd examples/esp-idf/twai_loopback
idf.py set-target esp32
idf.py build
read -r -p '输入实际串口: ' port
idf.py -p "$port" flash monitor
```

首次配置目标即可，已有配置先备份。退出monitor使用Ctrl+]。编译不要求接板，真实时序与波形需要硬件；[验证记录](../../validation/)列明已完成检查。前置：第40–42章；下一步按总目录继续。资料基线2026-10-29，教学代码为原创。
