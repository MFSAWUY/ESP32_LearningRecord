# 46 状态机分层设计与工程架构

[返回总目录](../../README.md) · ESP32-D0WD / 4 MB Flash / ESP-IDF 6.1。

## 明确各层职责

设备同时采样、显示、联网和存储时，越来越长的循环容易混淆业务与驱动错误。分层的目的不是增加文件，而是明确职责：驱动访问设备，服务管理连接和采样，业务决定动作，界面展示状态。

显示可以保留上次有效温度并注明年龄，上传可以丢弃过旧遥测，报警应明确是否接受过期数据。仅共享一个全局temperature无法表达有效性、时间和错误来源。

## 状态与事件表

网络可分DISCONNECTED、CONNECTING、ONLINE、BACKOFF；设备健康另设STARTING、READY、DEGRADED、ERROR。两者不强行合并，因为离线仍可采样和显示。

| 当前状态 | 事件 | 动作和下一状态 |
|---|---|---|
| DISCONNECTED | 启动 | 发起连接并设期限，进入CONNECTING |
| CONNECTING | 获得IP | 清重试计数，进入ONLINE |
| CONNECTING | 超时 | 计算重试时刻，进入BACKOFF |
| ONLINE | 断线 | 保留本地功能，进入BACKOFF |
| BACKOFF | 到期 | 重新连接，进入CONNECTING |

退避可取t_k=min(t_max,t_0×2^k)并加入小幅随机抖动，避免多设备同时重试。计算指数前限幅，防止长期运行整数溢出。每个等待状态必须有明确退出条件。

## 数据接口与所有权

样本包含序号、采样时刻、数值、有效标志、错误码；配置包含版本和周期；命令包含ID、期限、执行结果。遥测与控制命令的丢弃策略不同，不能只用一个无类型字符串通道混合处理。

队列工程是最小数据流骨架：生产者构造，队列复制，消费者处理。扩展sample_t后同步检查元素大小和序列化格式。不能把结构体原始内存直接当跨平台协议，填充和字节序可能变化。

把状态转换逻辑写为接收事件、输出动作请求的函数，I/O由服务执行。这样桌面测试可输入假事件和假时钟，覆盖超时路径；这些是测试输入，不能作为传感器实测展示。

## 错误分类与恢复预算

非法配置在工作前检查；单次传感器超时可以重试；持续缺失转入降级；堆损坏属于不应继续工作的内部故障。把一切失败都重启，会在硬件缺失时无限循环，并丢失现场。

重试需要预算，例如三次失败后降低频率，保留日志和界面，等待下一周期探测。每次重试都释放本轮资源。断网不应该自动擦除NVS；恢复出厂、重新配网和重刷固件属于不同强度操作。

控制输出应定义上电、失联、配置失败、重启和升级期间的状态。低压教学可默认关闭，但真实机械系统需要按应用定义安全状态，不可机械地保持上次输出。

## 测试与交付

检查每个状态能否退出，重复事件是否幂等，错误是否有证据。覆盖启动、断线重连、配置更新、资源失败和重复关闭命令。执行两次关闭应保持关闭，不能误写成翻转。

练习：为OLED时钟设计离线行为。参考：网络与显示状态独立，记录同步年龄，离线提示不清空本地时钟，重新连接仅更新必要数据。模块按职责拆分，明确的所有权和时间约束比堆砌设计模式更重要。

## 完整工程与运行

[源码](../../examples/esp-idf/tasks_queue/main/main.c)，[构建配置](../../examples/esp-idf/tasks_queue/CMakeLists.txt)。先激活IDF 6.1，从手册根目录运行。

Windows PowerShell：

```powershell
Set-Location examples/esp-idf/tasks_queue
idf.py set-target esp32
idf.py build
$port = Read-Host '输入实际串口'
idf.py -p $port flash monitor
```

Linux Bash：

```bash
cd examples/esp-idf/tasks_queue
idf.py set-target esp32
idf.py build
read -r -p '输入实际串口: ' port
idf.py -p "$port" flash monitor
```

首次配置目标即可，已有配置先备份。退出monitor使用Ctrl+]。编译不要求接板，真实时序与波形需要硬件；[验证记录](../../validation/)列明已完成检查。前置：第40–42章；下一步按总目录继续。资料基线2026-10-29，教学代码为原创。
