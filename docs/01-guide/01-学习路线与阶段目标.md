# 01 学习路线与阶段目标

前置：会使用文件管理器和 VS Code。配套：[语言与串口工程](../../examples/arduino/language_basics/)。返回：[总目录](../../README.md)。

## 这本手册怎样使用

本书的目标是让你独立完成一个能采集、显示、联网、恢复故障的嵌入式设备。ESP32 固件运行在开发板上；Windows 或 Linux 负责编辑、编译、烧录和监视；Python 上位机运行在电脑上。区分这三个位置，能够避免把电脑的 Python 包、Arduino 库和芯片驱动混为一谈。

学习采用“提出问题—理解模型—运行实验—观察证据—改变参数—解释结果”的循环。第一次读不要逐个背 API，而应能说清一个输入怎样变成输出。例如按键引脚是电压输入，GPIO 驱动把电压解释为 0/1，去抖逻辑生成一次事件，状态机据此改变显示。代码每一层都有对应的物理或逻辑责任。

你已有少量 C/C++ 与电路基础，可以先快速完成第 06、12 章的自测；答不出的部分返回详细推导。数学附录按需要阅读：学 LED 时先掌握欧姆定律；学滤波时再理解差分方程，不必在首次烧录之前读完所有理论。

## 阶段路线与验收

| 阶段 | 阅读与操作 | 必须能独立完成的结果 |
|---|---|---|
| A 环境闭环 | 02–05、18 | 确认串口，编译烧录，解释每一步在哪个设备运行 |
| B 基础回顾 | 06–17 | 计算 LED 电阻，解释指针与数组，找到一次越界错误 |
| C 单外设 | 19–31 | 按接线表完成 GPIO、ADC、I²C、OLED，解释测量误差 |
| D 联网 | 32–39 | 网络中断后恢复，区别连接成功和业务数据送达 |
| E 系统工程 | 40–53 | 用队列分离采样与显示，分析内存、复位、功耗和升级 |
| F 综合项目 | 54–62 | 电脑记录真实设备数据，设备异常时输出可理解的状态 |
| G 拓展选学 | 63–68 | 根据接口、内存与无线能力判断是否需要换硬件 |

阶段 A 不要求额外购买配件。数据线与 ESP32 可完成串口、系统信息和 Wi-Fi；现有四针 OLED 可完成 I²C 扫描与显示。等需要按键和模拟量时再购买面包板、电阻与电位器。这样每次增加设备都有明确的学习目的。

## 每次实验的固定流程

1. 读“适用硬件”和“接线”。确认 GPIO 编号、3.3 V 电平及共地，断电调整接线。
2. 在单独的示例目录打开工程，不把多个例子的 `setup()`、`loop()` 拼到一个文件。
3. 记录框架版本、板型、串口和实际接线。先构建，构建通过后再烧录。
4. 根据预期日志验收；串口乱码首先核对波特率，外设无响应先核对电源与接线。
5. 每次只改一个因素，例如闪烁周期从 1000 ms 改为 250 ms，观察是否符合预测。
6. 保存“问题—假设—检查—结论”，不要只保存最终代码。一次排障过程通常比重复运行十次更有价值。

建议建立个人实验记录，不要在手册原始示例中写入 Wi-Fi 密码后公开上传。记录可以采用下面的格式：

```text
实验：I2C 地址扫描
板卡：ESP32-D0WD / 4 MB Flash / CH340
框架：按 platformio.ini 和 pio pkg list 记录
接线：GPIO21→SDA，GPIO22→SCL，3V3→VCC，GND→GND
观察：发现一个地址；拔下屏幕后不再发现
结论：总线有应答，控制器型号仍未确认
下一步：按模块资料选择 SSD1306 或 SH1106 驱动
```

## Arduino、ESP-IDF 与 Python 的分工

Arduino 是 C++ 框架，提供 `pinMode()`、`digitalWrite()` 等方便的接口。PlatformIO 管理项目、库、编译和上传，它不是另一种编程语言。ESP-IDF 是乐鑫的原生开发框架，适合进一步理解驱动配置、FreeRTOS、分区和事件处理。先学 Arduino 能更快建立物理直觉，随后用 ESP-IDF 重做代表性实验，把便利接口与底层机制联系起来。

Python 用于串口数据采集、绘图、协议验证及算法仿真。MicroPython 则是运行在微控制器上的解释器，是另一条固件路线；它放在选学部分，不和主线工具链同时安装到同一板上。烧录新固件通常会替换原固件，应在理解备份与分区后进行。

## 如何判断真正学会

“能复制运行”是第一步；“能解释每个配置”是第二步；“断开传感器也能定位问题”是第三步。每章练习都要求至少一个预测和一次异常情况。没有硬件时可以运行数学仿真，但仿真输出不能写成真实测量结果。编译通过也不能替代接线、时间行为和网络恢复的真机检查。

练习：为什么 I²C 扫描发现 `0x3C` 仍不能证明屏幕是 SSD1306？答案要点：扫描只验证地址应答，多个控制器可以使用同一地址；还需型号资料或正确驱动后的显示行为。为什么电脑程序能运行不代表固件能运行？答案要点：CPU 指令集、运行库、外设和内存布局不同，需要目标工具链。
