## 测试什么，以及不能证明什么

前置：第52、54章。完整测试在[tests/test_tools.py](../../examples/python/tests/test_tools.py)，故障服务器在[replay_server.py](../../examples/python/replay_server.py)。测试分成纯函数、协议、进程回环、网络集成和真机验收。纯函数通过只能说明计算逻辑符合给定模型，不证明ADC电压准确；编译通过也不能证明接线正确。

两端运行同一命令，python替换为虚拟环境解释器：
```text
python -m unittest discover -s examples/python/tests -v
```
测试覆盖RC初始值和时间常数、低通收敛、采样混叠、平均电流边界、PID饱和后恢复、无效测量解析、超长/乱码/非有限数据拒绝、HTTP503和pySerial回环。回环测试启动真实子进程写临时CSV，并检查结果，避免仅测试一个函数却宣称完整采集链路正常。

## 故障服务器实验

Windows PowerShell：
```powershell
.\.venv\Scripts\python.exe examples/python/replay_server.py --fail-every 3 --port 8090
```
Linux Bash：
```bash
.venv/bin/python examples/python/replay_server.py --fail-every 3 --port 8090
```
另一个终端运行network_tool http http://127.0.0.1:8090/api/status。前两次200，第三次503；payload始终包含simulated=true。再设置--delay 6，客户端5秒超时应以非零状态结束。服务器只模拟网络行为，23.5℃是显式构造的测试值，不能混入真实采集数据集。

## 选择有效的断言

RC的解析结果应在t=0为0，在t=RC时为U(1−e⁻¹)，这比逐行重复实现更能捕捉错误。PID测试先施加极大误差，再反转误差，检查积分不会持续累积到无法恢复。协议测试包括true冒充整数和JSON的NaN扩展，因为这些输入常绕过宽松类型检查。

实时测试尽量使用time.monotonic测量超时，墙钟可能被NTP调整。网络测试由操作系统分配空闲端口，不能固定占用生产服务的1883。每次finally关闭server和socket，避免一次失败污染后续测试。Linux大小写敏感，CI应确实执行导入及命令，而不只检查文件存在。

## 真机故障矩阵

记录测试时间、固件摘要、板卡、工具链和操作步骤。逐项测试：上电、重启、拔传感器、断AP、恢复AP、错误凭据、满存储、OTA失败。执行器只接LED或安全低压负载。故障时应给出可解释状态并恢复，而不是不断重启掩盖问题。

练习：给协议增加humidity_pct范围检查。参考：应先区分传感器合法范围、业务允许范围和校准后的微小超界；保留原始数据便于诊断。不要默默把所有超界值截为0或100。验证结果见[报告](../../validation/REPORT.md)。来源：[unittest](https://docs.python.org/3/library/unittest.html)。下一步：第58章。
