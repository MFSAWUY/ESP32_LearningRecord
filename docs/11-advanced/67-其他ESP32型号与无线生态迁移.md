# 67 其他ESP32型号与无线生态迁移

[返回总目录](../../README.md)

## 先列能力需求再选型号

前置：第02、36、37、40章。迁移起点为[serial_info](../../examples/arduino/serial_info/)及[gpio](../../examples/esp-idf/gpio/)，不是直接给旧工程换一个board字符串后假设功能不变。你的主板是经典ESP32，教程中经典蓝牙、DAC和双核等知识不能不加核对地推广到全部型号。

| 系列 | 典型方向 | 迁移要检查 |
|---|---|---|
| 经典ESP32 | Wi-Fi、经典蓝牙、BLE与通用控制 | Flash/PSRAM占用、ADC2限制、启动脚 |
| ESP32-S3 | USB、显示、音频、图像与向量运算 | 不支持经典蓝牙；原生USB脚及PSRAM配置 |
| ESP32-C3 | 小型低成本RISC-V联网设备 | 单核、可用GPIO和外设差异 |
| ESP32-C6 | Wi-Fi6、BLE与802.15.4生态 | Wi-Fi仍需按频段核对；Thread/Zigbee需专用软件栈 |

上表不是完整芯片列表。型号后缀、模组Flash/PSRAM配置与板卡修订均可能改变可用引脚。带Type-C接口不等于有原生USB；它可能仍连接CH340等桥接器。RAM多不代表所有内存都可被DMA、ISR或特定外设直接访问。

## 有序迁移清单

建立旧板与新板的GPIO映射，列出启动、电源、USB、Flash和PSRAM保留脚。然后核对CPU架构、核数、任务亲和性、中断、ADC、PWM、I²S和睡眠唤醒源。把板级参数集中到配置层，业务逻辑尽量只依赖传感器、网络和存储接口。

在新板单独复制工程，设置正确target，先跑芯片信息、串口和外接LED，再逐步恢复总线、显示、网络、并发和低功耗。ESP-IDF使用idf.py set-target具体芯片；PlatformIO使用与实际模组内存一致的board配置。不要把启用PSRAM的选项复制到未安装PSRAM的板上。

两端编译命令相同，但USB设备路径、驱动和权限不同。涉及原生USB下载时，固件配置或复位模式可能改变枚举端口，应重新枚举而不是固守原端口号。迁移后重新执行[验收表](../../validation/HARDWARE_CHECKLIST.md)，旧板通过不能代替新板测试。

## Matter、Thread、Zigbee的关系

Wi-Fi和802.15.4属于不同连接技术；Thread基于802.15.4构建IPv6网络，Zigbee有自己的网络和应用体系。Matter定义互操作的应用与安全模型，可以使用不同承载，不能把Matter等同于Zigbee或某一种射频。选型时还要考虑边界路由器、配网控制器、证书、生态认证和更新维护。

本书优先用MQTT理解应用消息与状态，再将同样的设备模型映射到对应生态。一个温度读数除了数值，还需要单位、有效性、时间和设备身份；无线协议改变后这些业务语义仍然存在。

练习：把经典蓝牙串口项目移到S3需要什么改变？参考：不能原样使用Classic SPP，需要重新选择BLE GATT或网络接口，同时修改手机/电脑客户端协议，而非只改头文件。来源：[乐鑫产品目录](https://www.espressif.com/en/products/socs)、[ESP-Matter](https://docs.espressif.com/projects/esp-matter/en/latest/)。下一步：第68章。
