# 37 经典蓝牙与蓝牙串口

[返回总目录](../../README.md) · 前置：先完成17章及正文注明的基础；下一步：总目录第38章。

## 与BLE的区别及适用硬件

前置23章UART与36章BLE。经典蓝牙SPP通过RFCOMM提供串行数据通道，对应用表现接近字节流，适合现有串口工具和低速遥控。经典ESP32支持此路线；ESP32-S3、C3等不能因为名称相似就运行BluetoothSerial的SPP示例。源码通过CONFIG_BT_SPP_ENABLED检查构建配置，目标不支持时主动报错。

本例启动名为ESP32-Handbook-SPP的服务，把收到的蓝牙字节写到USB串口并回显给蓝牙端，把USB输入转发给蓝牙。它是桥接/回显实验，没有驱动实际控制负载。BLE GATT和SPP不是同一个服务，BLE扫描器通常不能用来测试SPP通道。

## 逐步理解代码

BluetoothSerial bt创建协议对象，bt.begin启动设备。loop每次最多从一个方向处理64字节，再处理另一个方向，然后delay(1)让出执行机会。有限处理量可避免持续输入一方长期占用loop，但不保证在任意速率下无损；缓冲满、连接中断或接收端不消费时都可能丢数据。

```cpp
for (unsigned i = 0; i < 64 && bt.available(); ++i) {
    int c = bt.read();
    Serial.write(c);
    bt.write(c);
}
```

read返回int是为了同时表示0～255字节与无数据的负值；本例先检查available。write发送原始字节，print则可能把数字格式化为字符；例如write(65)输出一个A，print(65)输出字符6和5。调试二进制协议时混用这两种方法会改变数据。

## Windows与Linux连接方法

先烧录固件，再通过操作系统蓝牙设置进行发现及必要配对。Windows若驱动支持SPP，会建立对应的传出COM端口；在设备属性或串口枚举中确认该端口，不能把USB CH340端口与蓝牙端口混用。用串口终端连接SPP COM，发送hello应原样收到，同时USB监视器显示hello。

Linux使用系统BlueZ工具发现和配对。可用bluetoothctl执行scan on，按实际MAC进行pair、trust和connect；具体SPP服务连接和RFCOMM设备绑定取决于发行版的BlueZ工具包。若使用rfcomm，先通过服务发现确认通道，再将真实MAC/通道绑定到本机设备，并检查设备权限。不要假设所有设备都使用RFCOMM通道1。绑定设备节点可能需要管理员权限，但后续Python程序不应整体以root运行。

通用SPP并非所有移动平台都开放；例如某些手机平台的应用无法使用任意SPP外设，这时应选择BLE方案或平台支持的协议，而不是不断修改ESP32名称。蓝牙适配器也要支持所需经典蓝牙能力，只有BLE的适配器不够。

## 协议与可靠性

SPP提供字节流，应用仍需定义分帧。沿用23章的长度限制、换行或长度前缀，并给命令设置超时与应答。两个相同帧可能因为业务重发重复出现，应该用序号和幂等语义处理。配对安全模式与用户确认流程需结合当前框架配置核对，不硬编码通用PIN就宣称安全。

## 验收与练习

测试两个方向各发送一行、拔开USB后重新供电再连接、主动断开蓝牙后重新连接。记录是否出现截断或旧缓存重放。练习：把桥接改成有界的info命令处理，只允许完整命令查询芯片信息；答案要点是串口监视器与蓝牙共用协议解析函数，而不是复制两套逐字节状态机造成行为差异。

## 完整源码与双平台操作

完整工程：[examples/arduino/bluetooth_serial](../../examples/arduino/bluetooth_serial/README.md)；逐行源码：[main.cpp](../../examples/arduino/bluetooth_serial/src/main.cpp)；依赖与编译配置：[platformio.ini](../../examples/arduino/bluetooth_serial/platformio.ini)。示例固件在ESP32上运行，Windows/Linux负责构建、烧录和监视。主线为经典ESP32-D0WD、4 MB Flash；不假定存在PSRAM或可编程板载LED。

1. 按第04/05章完成工具链安装，在手册根目录打开PlatformIO终端；确认所选环境为esp32dev。
2. 断电按本章接线，检查3.3 V逻辑和共地。只接本例所需部件，避免其他实验复用同一引脚。
3. 如有include/config.example.h，复制为config.local.h并调整自己的配置。联网项目必须修改Wi-Fi凭据；无真实凭据时仍可编译，但不能连接你的网络。
4. 两个平台均执行以下构建与设备枚举命令：

```text
pio run -d examples/arduino/bluetooth_serial
pio device list
```

Windows PowerShell（枚举后输入实际端口）：

```powershell
pio device list
$port = Read-Host '输入枚举出的实际串口'
pio run -d examples/arduino/bluetooth_serial -t upload --upload-port $port
pio device monitor --port $port --baud 115200
```

Linux Bash（将设备路径换成实际枚举结果）：

```bash
pio device list
read -r -p '输入枚举出的实际串口: ' PORT
pio run -d examples/arduino/bluetooth_serial -t upload --upload-port "$PORT"
pio device monitor --port "$PORT" --baud 115200
```

烧录前关闭其他串口监视器。Windows检查CH340驱动和端口占用；Linux检查用户组/udev与文件权限，不用sudo运行整个开发环境，也不把设备改为777权限。按本章预期现象记录实际结果，错误分支也要验证，不能用编译成功代替电路和运行验收。
