# 69 按症状检索的故障排查手册

[返回总目录](../../README.md) · 前置：第04、05、18章 · 下一步：第70章

## 排查原则：逐层缩小范围

把问题拆成电脑环境、USB串口、启动下载、固件、外设、电源和网络。每次只改变一个变量并记录结果。先用最小工程复现，再恢复复杂项目；不要同时换库、改线和调整多个菜单，否则成功后仍无法解释原因。

保留以下证据：板卡模组丝印、接线照片或表格、操作系统、框架版本、完整错误信息、复现步骤、正常时与失败时电压。分享日志前删除SSID密码、令牌、私钥和公网访问凭据。

## 电脑与烧录

| 症状 | 最小检查 | 下一步 |
|---|---|---|
| 插板无新端口 | 换确认可传数据的线，直接接电脑USB口 | Windows查设备管理器/CH340；Linux查设备枚举和内核日志 |
| Port busy / Permission denied | 关闭其它监视器、Python串口程序 | Windows检查端口名；Linux检查用户组，重新登录后生效 |
| Failed to connect | 确认目标esp32、端口、板卡供电 | 下载开始时按住BOOT，复位后按下载时序释放；查GPIO0外接电路 |
| 下载中断 | 降低upload_speed到115200，缩短线材 | 检查供电瞬态及USB集线器，不首先擦除Flash |
| Python/CMake找不到 | 在正确工具终端运行版本检查 | 不将Conda解释器强行替换为IDF内部Python |
| Windows能编译Linux失败 | 检查头文件大小写、绝对路径、脚本换行 | 使用同一锁定依赖，查看第一条真实编译错误 |
| 库API不存在 | 核对源码对应的Arduino/IDF版本 | Arduino 2.x与3.x的LEDC等API不能混用 |

Python可运行`python scripts/check_environment.py`，该脚本只读检查，不安装驱动。批量构建使用`python scripts/build_examples.py --kind arduino`。第04、05章给出完整平台命令，端口由枚举结果确定。

## 接线与传感器

OLED完全不亮：先查VCC/GND标识和模块额定电压，然后运行i2c_scan。无ACK说明先解决电气或地址，不急于换字体。能ACK但错位，查SSD1306/SH1106和128×32/128×64配置。部分模块排针顺序相反，不能按邻近网上图片直接接线。

ADC读数随Wi-Fi异常：经典ESP32的ADC2存在无线资源限制，优先用ADC1；检查衰减、校准和输入量程。输入悬空会漂移，GPIO34–39没有内部上下拉。不要将5V传感器模拟输出直接接入3.3V域。

温湿度偶发异常：核对SHT30的CRC、线长、上拉以及电源。错误值应标记无效。持续0并不一定是测得0，可能是程序把失败默认为零。多个I²C模块并联后上拉等效值降低，检查电流与上升时间。

电机一动板就重启：观察brownout信息，检查负载电源、共地、去耦、续流路径和回流布局。不能通过关闭欠压检测来修复供电不足。电源标称电流大不意味着线材和连接器没有压降。

## 网络与运行时

连不上Wi-Fi：先确认2.4GHz网络、SSID和认证方式，查网络事件及IP，再看DNS与服务器。获得IP不代表互联网可达。HTTP返回401先查令牌，超时先查IP/端口/路由/防火墙。MQTT仅监听localhost时ESP32无法连接；还要检查broker认证和客户端ID冲突。

周期性重启：记录复位原因和panic回溯；检查任务栈、非法指针、长时间阻塞、看门狗和供电。先定位崩溃位置，避免用自动重启掩盖错误。低功耗程序的深睡唤醒重启属于预期路径，应与崩溃区分。

## 练习与验收

人为将OLED地址改错，写出三步排查顺序。参考：扫描确认真实ACK→比较代码地址及地址移位约定→确认控制器配置；仅修改地址时无需重装驱动。最终问题记录应能让另一个人按步骤复现。来源：[Arduino故障排查](https://docs.espressif.com/projects/arduino-esp32/en/latest/troubleshooting.html)、[ESP-IDF致命错误](https://docs.espressif.com/projects/esp-idf/en/v6.1/esp32/api-guides/fatal-errors.html)。
