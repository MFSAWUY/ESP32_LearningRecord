## 验证层次

前置：第46、50、51章。可运行工具：[check_handbook.py](../../scripts/check_handbook.py)、[build_examples.py](../../scripts/build_examples.py)、[Python测试](../../examples/python/tests/test_tools.py)、[硬件验收表](../../validation/HARDWARE_CHECKLIST.md)。将测试分为静态检查、纯逻辑单元测试、构建、主机集成、真机和长时间运行；不同层次的证据不相互替代。

## Windows/Linux执行

在对应虚拟环境中运行：
```text
python scripts/check_handbook.py
python -m unittest discover -s examples/python/tests -v
python scripts/build_examples.py --kind arduino
```
Windows解释器为.venv\Scripts\python.exe，Linux为.venv/bin/python。原生IDF构建在已激活工具终端运行`python scripts/build_examples.py --kind idf`。脚本仅编译，不上传。使用--build-root可以将编译和库产物放入独立测试目录。--retry-failed保留已成功记录并补测失败或新增工程，源码再次修改的已通过项目须单独重新验证。

另有[PlatformIO托管IDF补充检查](../../scripts/build_idf_with_platformio.py)，它在副本中添加临时配置；此结果不能宣称原生EIM/idf.py安装已经验证。记录验证方法是可复现性的组成部分。

## 性能指标推导

测吞吐、延迟、抖动和资源上限，而不只测循环每秒运行多少次。任务响应延迟L=t完成−t触发，周期抖动可统计相邻周期与目标周期之差；报告均值、最大值和分位数，并说明样本数与测量范围。单次测得最大值不是系统绝对上界。

如果生产速率λ大于消费速率μ，队列会持续增长直到满；有限队列无法长期解决吞吐不足。若短时阻塞持续B秒，至少需要约λB条缓冲，再考虑突发余量。示例10Hz生产、消费最多停顿0.5秒，理论新增5条；8条队列能吸收这一次停顿，但持续慢消费仍会溢出。

## CI与发布

本仓库提供Windows/Linux桌面和IDF容器CI配置，但文件存在不等于已执行通过。CI应固定依赖、保存日志和固件摘要，失败时从第一条真实错误定位；下载失败归类为环境故障，编译错误归类为代码故障。不得把“跳过”计算为“通过”。

正式发布还需测试断网恢复、重启持久化、4MB分区容量、错误镜像、传感器缺失和长时间堆趋势。练习：为一个按键控制器写三个不能靠编译检测出的故障。参考：按键抖动、引脚反相和上电误动作；分别需要时间序列、接线和实际电平验证。真实结果见[验证报告](../../validation/REPORT.md)。下一步：第53章。
