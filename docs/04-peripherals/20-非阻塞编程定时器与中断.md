# 20 非阻塞编程定时器与中断

[返回总目录](../../README.md) · 前置：先完成17章及正文注明的基础；下一步：总目录第21章。

## 目标与事件处理模型

前置第19章和函数、指针基础。硬件定时器在指定时刻产生中断，中断服务函数只投递事件，loop负责日志等较慢处理。这里无需外接器件，每秒应该出现一次tick。理解“触发时刻”“处理开始时刻”“处理结束时刻”的区别比单纯会写定时器API更重要。

## 时间参数推导

定时器计数频率f=1MHz，所以一个计数的时间Δt=1/f=1μs。目标间隔T=1s，需要计数N=T/Δt=1,000,000。timerBegin(1000000)设置计数频率，timerAlarm(timer,1000000,true,0)设置报警值及自动重载。两者恰好数字相同是本例选择造成的，不是API要求；若要10ms报警，报警计数应为10,000。

Arduino-ESP32 3.x的timerBegin不是旧教程的timerBegin(编号,分频,方向)。不要混用2.x的timerAlarmWrite/timerAlarmEnable和本例接口。初始化失败可能来自资源耗尽，应检查返回指针而不是解引用空指针。

## 完整代码的同步方式

程序先创建容量为10的计数信号量，再注册中断。onTick调用xSemaphoreGiveFromISR，并在唤醒更高优先级任务时请求切换。loop调用xSemaphoreTake等待，拿到事件才打印。信号量将ISR和普通任务解耦，避免直接在ISR中调用Serial、Wire、网络或动态内存分配。

```cpp
BaseType_t wake = pdFALSE;
xSemaphoreGiveFromISR(ticks, &wake);
if (wake) portYIELD_FROM_ISR();
```

volatile只约束编译器对读写的优化，不是互斥锁，也不能保证复合操作原子性。本例用RTOS同步原语，不让ISR与loop一起修改普通计数器。ARDUINO_ISR_ATTR用于相应中断代码属性，但不能使被调用的任何复杂函数自动变得中断安全。

## 容量与实时性

若事件产生率为1次/秒，处理线程暂时被阻塞3秒，队列式计数可以积累事件；若超过10次，后续give可能失败。容量有限意味着必须明确“丢弃、覆盖、告警或施加背压”的策略。此演示容忍丢失，但产品应统计返回值或通过可中断安全的计数记录溢出。

日志时间与理想间隔的差是处理抖动，不等于硬件定时器误差。更精确地测量触发时序，应让中断控制合适GPIO并使用逻辑分析仪，而不以串口文字到达电脑的时间为准。

## 验收、排错和练习

正常时tick递增，time_ms大约每秒增长1000；它不是严格无抖动承诺。把报警改为10000后应大约100Hz，不要继续每次都打印大量文本，否则串口吞吐可能成为瓶颈。练习：每100个事件只打印统计一次，比较最大延迟；答案要点是在loop累加而非ISR打印，并把触发周期和显示周期分开。

## 完整源码与双平台操作

完整工程：[examples/arduino/timing_interrupt](../../examples/arduino/timing_interrupt/README.md)；逐行源码：[main.cpp](../../examples/arduino/timing_interrupt/src/main.cpp)；依赖与编译配置：[platformio.ini](../../examples/arduino/timing_interrupt/platformio.ini)。示例固件在ESP32上运行，Windows/Linux负责构建、烧录和监视。主线为经典ESP32-D0WD、4 MB Flash；不假定存在PSRAM或可编程板载LED。

1. 按第04/05章完成工具链安装，在手册根目录打开PlatformIO终端；确认所选环境为esp32dev。
2. 断电按本章接线，检查3.3 V逻辑和共地。只接本例所需部件，避免其他实验复用同一引脚。
3. 如有include/config.example.h，复制为config.local.h并调整自己的配置。联网项目必须修改Wi-Fi凭据；无真实凭据时仍可编译，但不能连接你的网络。
4. 两个平台均执行以下构建与设备枚举命令：

```text
pio run -d examples/arduino/timing_interrupt
pio device list
```

Windows PowerShell（枚举后输入实际端口）：

```powershell
pio device list
$port = Read-Host '输入枚举出的实际串口'
pio run -d examples/arduino/timing_interrupt -t upload --upload-port $port
pio device monitor --port $port --baud 115200
```

Linux Bash（将设备路径换成实际枚举结果）：

```bash
pio device list
read -r -p '输入枚举出的实际串口: ' PORT
pio run -d examples/arduino/timing_interrupt -t upload --upload-port "$PORT"
pio device monitor --port "$PORT" --baud 115200
```

烧录前关闭其他串口监视器。Windows检查CH340驱动和端口占用；Linux检查用户组/udev与文件权限，不用sudo运行整个开发环境，也不把设备改为777权限。按本章预期现象记录实际结果，错误分支也要验证，不能用编译成功代替电路和运行验收。
