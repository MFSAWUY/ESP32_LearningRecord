# 18 第一个工程串口输出与芯片信息

[返回总目录](../../README.md) · 前置：先完成17章及正文注明的基础；下一步：总目录第19章。

## 要解决的问题与前置知识

前置：第04/05章环境配置、第12～17章语言基础。本章建立“源文件→编译→固件→烧录→日志→修改”的闭环。你应能说明程序在哪里运行，以及日志来自哪个串口。Arduino不是只能使用Arduino IDE的语言；本例是由Arduino框架调用setup和loop的C++程序。

## 工程和程序逐步阅读

打开独立工程后先看platformio.ini：platform固定平台包，board选择经典ESP32通用4MB板，framework选择Arduino，monitor_speed只设置串口监视器波特率。上传速度和程序Serial.begin的速度是不同参数；一个下载失败并不说明Serial波特率错误。

src/main.cpp显式包含Arduino.h，避免依赖.ino预处理器偷偷插入头文件。setup只运行一次，在115200波特率启动串口，短暂等待后调用report。loop由框架重复执行，应迅速返回或让出CPU。delay(1)在本实验让后台任务得到执行机会；它不意味着控制周期精确等于1ms。

report读取真实芯片型号、核心数、修订、CPU频率、Flash容量、可用堆和复位原因。标称520KB SRAM并不等于所有空间都能供malloc分配：代码、静态变量、任务栈、协议栈和系统保留区域都占用资源。4MB Flash也不能全部作为单个应用，后续还会有引导、分区表和存储分区。不要用一次heap_free读数代替完整内存分析。

```cpp
line[used] = '\0';
if (overflow) Serial.println("error=line_too_long");
else if (strcmp(line, "info") == 0) report();
```

32字节数组最多容纳31字节有效字符，最后一个位置必须留给字符串终止符。代码持续丢弃溢出行剩余内容，直到换行后再恢复；因此超长输入不会把后半行误认为另一个有效命令。字符\r被忽略，\n作为帧结束，使Windows的CRLF和Linux的LF都能使用。

## 实验与验收

只连接USB数据线，不接其他外设。上电后找到chip、flash_bytes、reset等字段；在监视器发送info及换行，应该再次输出信息。发送abc应输出unknown_command，发送100个字符应输出line_too_long。随后重新发送info仍应工作，这才说明错误恢复完成。

串口乱码先检查115200、8N1和USB端口，而不是反复重装框架。没有日志时确认数据线可传数据、CH340枚举、串口没有被另一监视器占用；烧录卡在连接阶段时按住BOOT，按一下EN，再按工具提示释放。不要把电源指示灯当作可编程LED。

## 练习与参考思路

增加heap命令，只打印空闲堆；仍使用有界缓冲和完整命令匹配。答案要点是新增strcmp分支而不改变接收状态机。进一步增加每秒心跳时，使用millis无符号差值，不把整个loop替换成delay(1000)，以免串口命令被延迟。

## 完整源码与双平台操作

完整工程：[examples/arduino/serial_info](../../examples/arduino/serial_info/README.md)；逐行源码：[main.cpp](../../examples/arduino/serial_info/src/main.cpp)；依赖与编译配置：[platformio.ini](../../examples/arduino/serial_info/platformio.ini)。示例固件在ESP32上运行，Windows/Linux负责构建、烧录和监视。主线为经典ESP32-D0WD、4 MB Flash；不假定存在PSRAM或可编程板载LED。

1. 按第04/05章完成工具链安装，在手册根目录打开PlatformIO终端；确认所选环境为esp32dev。
2. 断电按本章接线，检查3.3 V逻辑和共地。只接本例所需部件，避免其他实验复用同一引脚。
3. 如有include/config.example.h，复制为config.local.h并调整自己的配置。联网项目必须修改Wi-Fi凭据；无真实凭据时仍可编译，但不能连接你的网络。
4. 两个平台均执行以下构建与设备枚举命令：

```text
pio run -d examples/arduino/serial_info
pio device list
```

Windows PowerShell（枚举后输入实际端口）：

```powershell
pio device list
$port = Read-Host '输入枚举出的实际串口'
pio run -d examples/arduino/serial_info -t upload --upload-port $port
pio device monitor --port $port --baud 115200
```

Linux Bash（将设备路径换成实际枚举结果）：

```bash
pio device list
read -r -p '输入枚举出的实际串口: ' PORT
pio run -d examples/arduino/serial_info -t upload --upload-port "$PORT"
pio device monitor --port "$PORT" --baud 115200
```

烧录前关闭其他串口监视器。Windows检查CH340驱动和端口占用；Linux检查用户组/udev与文件权限，不用sudo运行整个开发环境，也不把设备改为777权限。按本章预期现象记录实际结果，错误分支也要验证，不能用编译成功代替电路和运行验收。
