# 59 温湿度监测显示记录与联网

[返回总目录](../../README.md)

## 构成与数据路径

前置：第25、28、35、47、54章。完整工程：[environment_station](../../examples/projects/environment_station/)。额外需要3.3V兼容SHT30模块，其VCC/GND连接3V3/GND，SDA/SCL与OLED共用21/22。SHT30默认地址0x44，与OLED通常不同；若模块ADDR配置成0x45，应同时修改sensor.h地址。并联模块可能各带上拉，等效电阻变小，需要按第24章核对。

每2秒读取温湿度，校验CRC后生成同一条JSON，送到串口、本地文件和MQTT，并更新OLED。一个传感器源对应多个消费者，避免各消费者自行读取造成时间不一致。本例使用合作式主循环，传感器20ms等待有明确上限；需要更严格刷新时移植到第44章队列结构。

## 传感器换算

SHT30提供16位原始值S，温度T=−45+175S/65535，湿度RH=100S/65535。每个两字节数据后有CRC8，多项式0x31、初值0xFF。CRC失败必须丢弃本次读数；两个字节对调会产生看似合理却错误的结果，因此先组合高低字节再换算。65535来自传感器编码规定，不能直接套用ADC中另一种量化步长定义。

## 两个平台运行

在工程目录复制include/config.example.h为config.local.h，填写Wi-Fi与MQTT参数。Windows使用Copy-Item，Linux使用cp。随后：
```powershell
pio run
pio device list
$serialPort = Read-Host '输入枚举出的实际串口'
pio run -t upload --upload-port $serialPort
pio device monitor --port $serialPort
```
```bash
pio run
pio device list
read -r -p '输入枚举出的实际串口: ' serial_port
pio run -t upload --upload-port "$serial_port"
pio device monitor --port "$serial_port"
```
两端broker安装和认证见第35章。topic为handbook/environment/telemetry。未配置网络时，OLED和串口仍可使用。电脑记录使用第54章serial_tool，先关闭PlatformIO监视器。

## 文件系统与可靠性

LittleFS.begin(false)失败时不会自动格式化已有数据。初次使用可在确认不需要保留该分区数据后，单次将false改为true初始化，运行一次后改回false；该操作只针对文件系统分区，不能混淆为擦除整片Flash。日志64KiB轮换到previous.jsonl，本例不是掉电原子数据库，重命名与写入之间可能断电。严肃采集应增加记录校验、序号和恢复策略。

2秒一条、每条约120字节，约5.18MB/天，说明有限Flash日志只保留短时间历史；长期数据交给电脑、SD或服务器。MQTT发布使用QoS0，publish返回成功只表示本地发送流程接受，不证明数据库落盘。网络离线期间本例不会无限缓存内存，串口和文件保存可用于后续补传设计。

## 验收与改造

拔掉SHT30后valid=false且温湿度null，OLED提示错误；重新接回恢复。断开MQTT不应停止采样。重启后查看日志是否追加；文件系统不可用时应明确报告。练习：加入离线补传。参考方案是记录单调序号、接收端幂等处理和已确认位置，不能每次重连把全部历史重复计数。来源：[Sensirion SHT3x资料](https://sensirion.com/products/catalog/SHT30-DIS-B)、[PubSubClient 2.8 API声明](https://github.com/knolleary/pubsubclient/blob/v2.8/src/PubSubClient.h)。下一步：第60章。
