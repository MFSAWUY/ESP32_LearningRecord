## 可控输出与故障默认值

前置：第19、30、34、53、56章。完整工程：[low_voltage_controller](../../examples/projects/low_voltage_controller/)。先用GPIO25→330Ω→LED→GND验证；LED极性错误不会发光。增加风扇或电机时必须使用适配MOSFET/驱动和独立电源，电感负载需续流路径，不能从GPIO直接供电。实验只使用安全低压负载。

固件上电先把输出置低，再启动网络。控制命令具有30秒租约，过期或Wi-Fi断开后关闭输出；GET状态不续租。因此浏览器界面刷新不会让输出永久保持开启。输出默认关闭是此实验的设计决定，不等同于所有工业设备的安全策略，例如冷却系统可能需要故障保持运行。

## 配置、接口与两端操作

复制include/config.example.h到config.local.h，填Wi-Fi及至少16字符的随机CONTROL_TOKEN。空令牌禁用远程控制。Windows：
```powershell
pio run
pio device list
$serialPort = Read-Host '输入枚举出的实际串口'
pio run -t upload --upload-port $serialPort
pio device monitor --port $serialPort
```
Linux：
```bash
pio run
pio device list
read -r -p '输入枚举出的实际串口: ' serial_port
pio run -t upload --upload-port "$serial_port"
pio device monitor --port "$serial_port"
```
串口每2秒打印IP与输出状态。电脑端运行第56章dashboard；环境变量ESP32_TOKEN应和设备配置一致。

GET /api/status返回uptime_ms、led和lease_ms。POST /api/led?on=1开启，on=0关闭，要求Bearer令牌；错误令牌401，非法参数400，未知路径404。只有成功控制命令更新lastCommand。使用POST表达有副作用操作，避免浏览器预取GET就开启设备。

## 代码与物理模型

setOutput同时更新状态变量与GPIO，使接口报告与输出命令一致；它仍不能证明负载实际运作。加入转速、电流或行程传感器才能闭环确认。pollWifi保持重连，server.handleClient处理请求，租约逻辑持续检查。软件无法控制芯片复位前的引脚电平，MOSFET门极还需硬件下拉，防止启动阶段浮空误动作。

电阻近似R=(3.3−2.0)/0.004≈325Ω，可选330Ω。对MOSFET，导通损耗近似P=I²Rds(on)，必须使用数据手册在实际3.3V栅压下的参数，不能把阈值电压当成完全导通电压。开关过渡损耗与PWM频率有关，详见第30章。

## 验收与练习

开启LED后等待超过30秒应自动关闭；网络掉线也关闭；重启不恢复此前开启状态；错误令牌不能改变输出。公网部署前应更换为经过验证的TLS方案或受控网关，本项目不提供端口映射到互联网的步骤。练习：增加命令ID和幂等返回。答案要点：重试相同ID只能返回之前结果，不能重复触发一次性动作；保存范围和重启语义也要明确。下一步：第61章。
