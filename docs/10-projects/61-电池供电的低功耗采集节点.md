# 61 电池供电的低功耗采集节点

[返回总目录](../../README.md)

## 唤醒、采样、发送、睡眠

前置：第28、35、48章。完整工程：[battery_node](../../examples/projects/battery_node/)。此项目需要SHT30和适配的电源方案。先用USB观察流程，再测量低功耗；CH340、稳压器和电源指示灯会显著增加开发板电流，因此不要预期USB开发板达到芯片数据手册中的深睡电流。

一次启动执行：增加RTC保留计数→I²C采集→最多8秒等待Wi-Fi→有限超时MQTT发送→关闭Wi-Fi→设置60秒唤醒→深睡。deep sleep后重新从setup开始，普通RAM变量重新初始化；RTC_DATA_ATTR保留变量也会在完全断电后丢失。bootCount适合观察睡眠周期，不适合作为永不重复的业务ID。

## 能耗推导

同一供电侧测量，活动电流Ia，休眠电流Is，活动时长ta，周期T，平均电流为Iavg=(Ia·ta+Is·(T−ta))/T。本例“睡60秒再启动”，所以实际T=60秒+活动时长，不能把60直接当总周期。假设活动120mA持续2秒、休眠0.15mA持续60秒，Iavg=(240+9)/62≈4.016mA。理想1000mAh电池约249小时，但实际容量、效率、自放电和温度会缩短时间。

不同电压侧优先比较能量：电池可用能量E≈Vbat·C(Ah)，负载平均功率Pavg，续航≈ηE/Pavg。不能将5V负载mA与3.7V电池mAh直接相除。联网超时把活动时间从2秒增加到8秒，可能比优化休眠微安更影响总续航。

## 构建与观测

复制配置并填Wi-Fi、MQTT。Windows：
```powershell
pio run
pio device list
$serialPort = Read-Host '输入枚举出的实际串口'
pio run -t upload --upload-port $serialPort
pio device monitor --port $serialPort
```
Linux：
```bash
pio run
pio device list
read -r -p '输入枚举出的实际串口: ' serial_port
pio run -t upload --upload-port "$serial_port"
pio device monitor --port "$serial_port"
```
串口应输出有效或无效采样、publish_local_result、active_ms、wake_reason，随后安静约60秒。MQTT为QoS0，发送成功不能证明应用接收；若需要可靠离线缓存，应增加NVS队列和业务确认，并评估擦写寿命与额外唤醒时间。

## 测量与验收

电流表串联于一个明确的电源入口，不能将电流档并联电源。普通万用表可能看不到Wi-Fi瞬态峰值，量程切换的负担电压还可能导致brownout；先确认测量装置不改变被测系统。记录板卡完整功耗，分别测有无OLED、有无指示灯的差异。

验收包含AP不存在仍按超时睡眠、传感器缺失仍能报告错误、深睡重复唤醒、掉电后计数重置。练习：改成每分钟整点采样。参考：先测本轮活动时间，再扣除它计算睡眠长度，同时处理活动超时和RTC误差。来源：[ESP-IDF睡眠模式](https://docs.espressif.com/projects/esp-idf/en/v6.1/esp32/api-reference/system/sleep_modes.html)。下一步：第62章。
