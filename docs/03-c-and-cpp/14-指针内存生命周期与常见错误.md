# 14 指针、内存、生命周期与常见错误

前置：[13 数组和函数](13-函数数组字符串与边界检查.md)。完整示例：[language_basics](../../examples/arduino/language_basics/)。返回：[总目录](../../README.md)。

## 指针是地址，不是数据本身

`int32_t value = 100;` 创建一个整数对象；`int32_t* ptr = &value;` 将它的地址存入指针；`*ptr = 200;` 经地址修改同一个对象。`&` 在此处取地址，`*` 在此处解引用；它们在其他表达式中还可能有位与、乘法等含义，必须根据语境判断。

```cpp
int32_t value = 100;
int32_t* ptr = &value;
if (ptr != nullptr) {
    *ptr += 25;
}
// value 现在为 125
```

空指针检查只排除空地址，不证明指针指向仍然有效的对象。指针也不自动知道分配大小，因此“非空”不等于可安全读取一百个元素。指针算术按元素大小前进，`ptr+1` 对 `int32_t*` 表示下一个整数，不是下一个字节。

## 存储区域与生命周期

局部自动变量通常放在任务栈中，进入作用域创建，离开后生命周期结束。全局和 `static` 对象通常存在整个运行期。堆内存通过 `malloc/new` 动态取得，必须在不再使用时释放。代码和常量还可能在 Flash 映射区或其他区域，嵌入式实际布局由链接与内存能力决定。

| 对象 | 生命周期 | 典型问题 |
|---|---|---|
| 函数局部数组 | 当前调用/作用域 | 返回其地址后继续使用，或数组过大耗尽任务栈 |
| 函数局部 `static` | 程序运行期 | 多任务共同访问导致竞争 |
| 全局缓冲 | 程序运行期 | 所有权不清，多个模块任意修改 |
| 动态分配对象 | 分配到释放之间 | 泄漏、重复释放、释放后访问、碎片 |

下面是错误示例，仅用于识别，不要放入实验：

```cpp
// 错误：局部数组在函数返回后失效。
const char* bad_name() {
    char name[] = "ESP32";
    return name;
}
```

可替代为返回拥有数据的对象，或让调用方提供缓冲与容量。常量字符串字面量具有更长存储期，但不能通过指针修改它。把指针强制转换成另一类型不会创造新的有效对象，也不会绕过对齐与别名规则。

## 所有权与借用

设计函数时问三件事：谁创建对象，谁可以修改，谁负责销毁？只在调用期间观察一个缓冲，属于借用；如果要异步保存其地址，调用方必须保证更长生命周期。传给 FreeRTOS 任务的参数常在任务真正运行前已经离开原函数，这是常见悬空指针来源。

队列通常按配置大小复制数据本体；如果队列元素只是一个指针，复制的是地址，所指数据不会自动复制。用值传递的小结构体能简化所有权；大缓冲需要明确池化、引用计数或交接协议。第 44 章将把这些原则应用到任务通信。

## 动态内存与资源预算

入门工程尽量使用固定容量缓冲，便于知道最大占用。动态分配并非禁止，但要检查失败、明确释放时刻并避免高频反复变长。总空闲堆很多仍可能无法分配一个大块，因为最大连续区域不足；堆还可能分成具有不同 DMA、字节访问或外部内存能力的区域。

栈与堆是不同预算。打印“还剩 100 KB 堆”不能证明某个只有几 KB 栈的任务能创建大型局部数组。递归、格式化输出及库调用都消耗栈。过深递归在单片机上尤其需要界限，适合改为受控迭代或显式小缓冲。

## const、volatile 与并发

`const` 限制通过某个接口修改对象；`volatile` 告诉编译器对象可能以其看不到的方式变化，常用于设备寄存器语义。`volatile` 既不提供互斥，也不让 `counter++` 成为原子操作。两个任务各自“读取、加一、写回”可能丢失更新，需用适当原子、锁或消息机制。

同样，不要因为 ESP32 是 32 位就假定任意结构体更新都是原子的；复合状态更新、对齐、编译器与硬件内存顺序都影响行为。基础示例只在同一执行上下文修改统计对象，避免在尚未学习并发前引入隐藏竞争。

## 练习与验收

查看 `language_basics` 的命令数组：它是持久对象，解析函数只在有效字符串期间借用指针，不保存指针供以后访问。周期数据通过值对象交给统计器，统计器只保存数值，不指向即将销毁的临时对象。

练习：为什么返回 `new` 出来的数组地址虽不悬空却仍可能不好？答案：调用者要知道怎样释放，错误路径容易泄漏，应明确所有权或用 RAII。为什么把局部数组改为 static 不是所有问题的通用修复？答案：引入共享状态和非重入行为。发现每次重连后堆持续下降，应记录什么？答案：重连次数、当前及最低堆、最大块、对象创建销毁路径，而不是只重启掩盖问题。
