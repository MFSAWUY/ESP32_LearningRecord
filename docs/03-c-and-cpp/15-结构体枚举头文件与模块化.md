# 15 结构体、枚举、头文件与模块化

前置：[14 指针与生命周期](14-指针内存生命周期与常见错误.md)。完整代码：[language_basics](../../examples/arduino/language_basics/)，重点阅读 `include/model.h`、`src/model.cpp` 与 `src/main.cpp`。返回：[总目录](../../README.md)。

## 把相关数据组织在一起

采样值通常不能脱离时间和有效性独立理解。用三个散落的全局变量保存时间、数值和状态，会让修改者容易遗漏其中一个。结构体将同一个概念的字段组合起来：

```cpp
struct Reading {
    uint32_t at_ms;
    int32_t value_mv;
    bool valid;
};
```

`Reading sample{1000, 1200, true};` 表示在 1000 ms 时得到一个有效的 1200 mV 值。单位放进字段名，避免后续模块把 mV 当 V。结构体的字段命名顺序不是外部协议；编译器可能为对齐插入填充，因此不能默认 `sizeof(Reading)` 等于字段大小简单相加。

本书基础工程的 Reading 是明确标记的模拟数据，没有读取 ADC。后续接入真正传感器时，保持结构体接口不变，把采样函数换成驱动读取，同时正确处理 `valid=false` 的错误情况。这就是把数据模型与具体硬件分离的价值。

## 枚举让状态有名字

使用 `0/1/2` 代表运行状态会让代码难读，且容易混用数值。作用域枚举为有限状态提供明确名称：

```cpp
enum class RunMode : uint8_t { Running, Paused };
RunMode mode = RunMode::Running;
if (mode == RunMode::Paused) {
    // 继续处理命令，但暂停采样
}
```

`enum class` 的值不会像普通整数一样隐式混用，名称也被限定在枚举作用域内。状态转换由命令处理层负责，统计器不自行改变设备模式。复杂系统的状态还可能有连接中、故障、恢复等，但每增加一个状态都应定义进入、退出和允许事件，而不是只添加一个枚举值。

## 声明、定义与链接

头文件描述模块提供什么，源文件定义具体怎样实现。`bool parse_period(...);` 是函数声明；包含函数体的版本才是定义。其他 `.cpp` 文件包含头文件后可以调用它，链接阶段再把调用与实现连接起来。

`model.h` 使用包含保护，避免同一个翻译单元重复定义类型：

```cpp
#ifndef HANDBOOK_MODEL_H
#define HANDBOOK_MODEL_H
#include <cstdint>
// 类型、类与函数声明
#endif
```

不要把可变全局变量定义放进被多个 `.cpp` 包含的头文件，否则可能产生多重定义。需要共享对象时优先通过函数参数传递；确实需要全局对象，可在头文件声明 `extern`、在一个源文件定义，但这也增加了模块耦合。小的内联函数和模板有自己的定义规则，应按语言规则使用，而不是为了“解决链接错误”把全部代码复制进头文件。

## 一个可维护的依赖方向

本例分三层：`main.cpp` 负责串口、调度和 Arduino API；`model.cpp` 负责参数解析与统计；`model.h` 定义两者之间的类型和接口。模型层不包含 `Arduino.h`，可以使用桌面 C++ 工具测试算法而不需要开发板。本例附带 [模型测试](../../examples/arduino/language_basics/tests/test_model.cpp) 和仅用于桌面测试的 CMake 配置；ESP32 主固件仍通过 PlatformIO 构建，两种运行目标要明确区分。

统计器只暴露 `add()`、`reset()`、`count()`、`mean_mv()` 等操作。调用方不直接写其内部累计和，因而不容易让“计数为零但累计和非零”这种不一致状态出现。模块化的目的就是让无效状态更难发生，不是单纯增加文件数量。

## 协议不直接复制内存布局

如果需要把 Reading 发给电脑，逐字段输出或编码：

```text
sample,1000,1200,1
```

规定字段顺序、单位、分隔符与换行。二进制协议还需规定字节序、长度、版本和校验。直接把结构体地址传给发送函数，会把编译器填充、类型大小和端序泄漏到协议，换编译器或芯片后容易出错。使用 `packed` 也不会自动解决端序、对齐访问和协议版本问题。

## 实验与练习

先只修改 `main.cpp` 中模拟值的生成公式，观察统计值改变而命令解析不受影响。再在 `model.cpp` 中修改允许的周期范围，并同步修改 README 与错误提示；这个练习说明“配置规则”是一份需要保持一致的接口约定。

练习一：头文件有声明但忘记加入实现文件，通常在哪一步失败？答案：编译可能通过，链接报告未定义引用。练习二：同名变量在两个源文件都有定义会怎样？答案：通常链接报多重定义；在不同内部作用域的同名变量另论。练习三：如何让接收方知道数值是 mV？答案：在协议规格与字段名中固定单位，必要时带版本，而不依赖口头约定。
