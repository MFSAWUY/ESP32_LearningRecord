# 13 函数、数组、字符串与边界检查

## 把行为分成可理解的函数

函数应完成一个清楚的任务，并约定参数、返回结果和失败含义。示例中的 `parse_period()` 将文本转换为毫秒数，成功返回 `true` 并更新输出参数，失败返回 `false` 且保留输出参数原值。这样命令处理层不必同时承担数字解析和状态管理。

```cpp
bool parse_period(const char* text, uint32_t& output_ms);
```

`const char*` 表示函数不会通过该指针修改输入文本；`uint32_t&` 是输出变量的引用。函数声明让调用者知道接口，定义提供实现。按值传递适合小整数；大型结构体可用 `const&` 避免拷贝；只有确实要修改调用者对象时才使用非 const 引用。

拒绝没有边界检查的转换。`atoi()` 无法方便地区分非法输入与合法的零，示例使用 `strtoul()`，检查是否有数字、是否完整消费文本、是否超范围，并显式拒绝负号。协议输入是不可信数据，即使发送者是自己的调试脚本，也可能包含粘贴错误和乱码。

## 数组与长度是成对的信息

`int samples[4]` 分配四个元素，合法下标为 0–3。C/C++ 不会自动阻止所有越界访问，越界可能破坏旁边的状态，使故障很晚才出现。局部数组可以用 `sizeof(samples)/sizeof(samples[0])` 得到元素数，但当它传入函数后退化为指针，这个公式不再代表原数组长度。

```cpp
int32_t minimum(const int32_t* values, size_t count) {
    // 本片段前提：values 非空，count > 0。
    int32_t result = values[0];
    for (size_t i = 1; i < count; ++i) {
        if (values[i] < result) result = values[i];
    }
    return result;
}
```

真实公共接口需检查空指针和零长度，并明确失败返回方式；本片段用前提强调为什么函数签名只有一个指针不足以说明安全。`std::array<T,N>` 可以把固定长度带入类型，适合静态资源明确的嵌入式代码。

## C 字符串为何要多留一个字节

字符串 `"status"` 有六个可见字符，C 字符数组还需末尾的 `\0`，因此至少七个字节。`strlen()` 遇到零才停止，若缓冲没有结束符，它可能读出数组之外。缓冲容量与当前文本长度必须分别记录。

本例使用 64 字节命令缓冲，最多保存 63 个字符再补零；读到换行才处理。遇到过长行时进入丢弃状态，直到换行后恢复，不能把超长命令的尾部误当成下一条有效命令。忽略 `\r`、使用 `\n` 分隔，使 Windows 的 CRLF 和 Linux 的 LF 都能工作。

字符串拼接使用带容量的 `snprintf()` 并检查返回值：

```cpp
char output[32];
int n = snprintf(output, sizeof(output), "period=%lu", (unsigned long)period_ms);
if (n < 0 || size_t(n) >= sizeof(output)) {
    // 编码失败或被截断；不能把截断文本当完整协议发送
}
```

`snprintf` 返回本来需要的字符数，不含末尾零。使用它比无界写入更安全，但忽略截断仍可能造成协议歧义。`String` 类易用，却可能动态分配，长期运行的协议与日志应评估堆碎片和内存增长。

## 从字节流恢复消息

串口一次 `read()` 读到的字节不等于完整消息。示例的处理顺序为：读取可用字节→累积到缓冲→遇到换行→补结束符→解析命令→清空长度。一次循环最多读取有限字节，让周期任务继续运行。网络 TCP 同样是字节流，也需要分隔符或长度字段；它不会为每次应用发送保留消息边界。

命令设计为 `help`、`status`、`pause`、`resume`、`reset`、`period N`。错误输出带明确原因，不执行部分有效命令。`period 250abc` 必须失败，不能默默使用开头 250。协议稳定后可以在 Python 自动测试里逐项验证。

## 实验与练习

依次发送 `period 100`、`period 0`、`period -20`、`period 100x`、空行和超过 63 字符的一行。只有第一条应修改周期，超长行之后再发 `status` 应正常。把串口换行从 LF 改成 CRLF，结果应相同。若发送器没有换行，命令暂不执行符合分帧规则。

练习：`char name[4] = "ESP32";` 有何问题？答案：五个字符加结束符需要六字节。为什么 `sizeof(pointer)` 不是字符串长度？答案：它只给指针对象大小。一个函数收到数组指针后是否知道它剩余多少元素？答案：通常不知道，必须显式传长度或使用携带长度的容器。
