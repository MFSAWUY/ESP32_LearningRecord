# 17 预处理、编译、链接与构建系统

前置：第 12–16 章，已安装 PlatformIO。完整工程：[language_basics](../../examples/arduino/language_basics/)。返回：[总目录](../../README.md)。

## 从文本到可执行固件

源文件首先经过预处理：处理 `#include`、条件编译和宏替换。随后编译器分析 C++ 语法与类型，优化并生成目标机器相关代码；汇编器产生目标文件。链接器把多个目标文件和库连接起来，解析函数引用，并根据链接脚本安排代码与数据的地址。最后工具从 ELF 等构建产物生成用于 Flash 的固件镜像。

经典 ESP32 的指令集不是电脑 x86_64，因此需要交叉编译器。Windows 和 Linux 主机运行不同平台的编译工具，但都能生成相同目标架构的固件。Linux 上直接执行 `firmware.bin` 不会把它变成 Linux 程序；烧录还必须包含正确启动配置与分区地址。

## 不同错误对应不同阶段

| 现象 | 常见阶段 | 优先检查 |
|---|---|---|
| 找不到头文件 | 预处理/编译 | 依赖是否安装、包含路径、大小写是否一致 |
| 缺分号、类型不匹配 | 编译 | 第一条真实错误附近的代码；后续错误可能是连锁反应 |
| undefined reference | 链接 | 函数有无定义、实现文件是否参与构建、签名是否一致 |
| multiple definition | 链接 | 头文件是否定义了重复全局对象、实现是否被重复包含 |
| 镜像超过分区 | 大小检查/链接后 | 分区表、功能组件和代码资源大小 |
| 无法打开串口 | 上传 | 端口、权限、驱动、占用，与 C++ 语法无关 |

VS Code 的 IntelliSense 是编辑器索引，索引错误与实际编译错误要分别判断。先看终端中的完整构建结果，避免为消除波浪线盲目修改能工作的工程。

## PlatformIO 工程各文件的责任

`platformio.ini` 声明平台、板型、框架与构建选项；`src/` 放参与编译的实现；`include/` 放本项目头文件；`lib_deps` 指定第三方依赖；`.pio/` 保存自动生成的构建缓存。修改生成目录不是维护源码的方法，下一次构建可能覆盖这些更改。

本例固定平台版本，避免未来安装时自动切换核心 API：

```ini
[env:esp32dev]
platform = espressif32@8.0.0
board = esp32dev
framework = arduino
monitor_speed = 115200
upload_speed = 115200
build_flags = -Wall -Wextra
```

`build_flags` 开启更多诊断，不代表所有库都没有警告。项目若发现新警告，应定位是否来自本书源码或框架依赖并记录，不用全局屏蔽警告掩盖问题。库依赖应写确定版本；锁定源码依赖仍需记录主机工具和真正安装的包，才能复现环境。

## 构建与检查的常用命令

在示例目录的 PlatformIO Core CLI 中，两平台均可执行：

```text
pio run
pio pkg list
pio run --target size
pio run --verbose
```

详细输出用于核对真实编译器、包含路径和链接参数，不需要每次都打开。只在配置变化或怀疑缓存干扰时清理：`pio run --target clean`。如果上一次编译失败是依赖缺失，清理不会让依赖凭空出现。

源文件修改后通常只重编译受影响的部分；头文件被多个源包含时可能触发更多重编译。所谓增量构建依赖正确的依赖关系与时间/内容判断，不能把旧固件文件的存在当成本次构建成功。必须检查本次命令返回状态和最终结果。

## Arduino 与 ESP-IDF 工程的联系

Arduino 平台为用户准备了启动流程与较方便的 API，底层仍使用芯片工具链和许多 IDF 能力。原生 IDF 工程显式使用 CMake、组件和 `app_main()`，通过 Kconfig/menuconfig 配置系统功能。`idf.py` 是统一调度构建、配置、烧录与监视的工具，不是一种编程语言。

不能将一段 Arduino `setup()` 代码直接放入原生 IDF 就期待自动运行，也不能把 IDF 6.1 的任意 API 当作 Arduino 当前基础版本一定具备。第 40–42 章使用独立工程对照接口与生命周期，而不是在初学阶段混合两套框架。

## 可复现构建与后续实验

记录源码版本、平台版本、目标芯片、依赖、关键配置、命令和构建结果。Flash 使用量与 RAM 静态使用量不是完整运行峰值；Wi-Fi 堆分配、任务栈和外设缓冲还需运行时测量。只构建成功可声明“编译通过”，不能声明 OLED 显示、网络重连或电气连接已经实测。

练习：`model.h` 中声明 `parse_period`，源文件却写成另一个参数类型，会发生什么？答案：调用者寻找声明对应的符号，可能链接失败；编译器按完整签名区分。为什么 Arduino 中 `main.cpp` 需要 `#include <Arduino.h>`？答案：普通 `.cpp` 不享受 `.ino` 预处理的全部便利，必须显式获得声明。库升级后旧 API 不存在，应该怎么做？答案：确认版本变更，按迁移文档调整或恢复锁定版本，不复制未知头文件拼凑环境。
