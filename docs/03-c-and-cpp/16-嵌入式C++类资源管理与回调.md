# 16 嵌入式 C++ 类、资源管理与回调

前置：[15 模块化](15-结构体枚举头文件与模块化.md)。完整代码：[language_basics](../../examples/arduino/language_basics/)。返回：[总目录](../../README.md)。

## 类将状态与合法操作组合

结构体和类在 C++ 中都可以包含数据与成员函数，主要默认访问权限不同。实际设计重点是哪些状态可以公开修改。统计器把计数、累计和、最小值和最大值设为私有，只允许通过 `add()` 和 `reset()` 修改：

```cpp
class Statistics {
public:
    bool add(const Reading& reading);
    void reset();
    uint32_t count() const;
    double mean_mv() const;
private:
    uint32_t count_ = 0;
    int64_t sum_mv_ = 0;
};
```

成员函数后的 `const` 表示经该函数不修改对象的普通成员。调用者可以读取均值，却不能随便把 `count_` 改成一个与累计和无关的数。`add()` 明确拒绝无效样本及计数耗尽，错误路径也属于接口的一部分。

对象可以直接放在栈或静态存储中，使用类不等于必须 `new`。本工程的统计器不进行动态分配，资源占用固定。类的封装是组织代码的机制，不应默认认为它会造成不可接受的运行开销。

## 构造、析构和 RAII

构造函数建立可用状态，析构函数在对象生命周期结束时释放其拥有的资源。RAII 把资源占用与对象生命周期绑定，可用于内存、文件、锁和设备会话。这样函数提前返回时也能执行清理，减少遗漏释放的错误路径。

例如标准库的 `std::unique_ptr<T>` 表示独占所有权，离开作用域会删除对象；`std::lock_guard` 表示在作用域内持有匹配的互斥锁。嵌入式使用前要确认库支持、异常设置与具体 RTOS 对象的封装。对 FreeRTOS 信号量应使用匹配的包装与释放方法，不能随意用标准库类包住不兼容句柄。

全局对象的构造可能早于 Arduino `setup()`。因此构造函数适合初始化成员值，访问硬件通常放在显式 `begin()` 中，待系统初始化完成后调用。不要依赖不同源文件中全局对象的初始化先后关系。

## 拷贝与所有权规则

含有一个原始指针的默认拷贝只是复制地址。如果两个对象都认为自己负责释放同一块内存，就可能重复释放。资源拥有者应明确禁止拷贝、实现正确的拷贝/移动，或者使用表达所有权的标准组件。简单数值结构体可以按值复制，不能把所有对象都当成需要复杂管理的资源对象。

本例 Statistics 保存纯数值，不拥有外部内存。读取一个 Reading 时按 `const&` 借用它，只在函数调用期间使用字段，不存储其地址。这个约定保证周期函数中的局部 Reading 离开作用域后不会留下悬空引用。

## 回调与上下文

回调是把“事件发生时要做什么”交给另一层调用。例如定时器到期、Wi-Fi 断开或串口数据到达时调用指定函数。普通函数指针没有自动携带对象实例；需要状态时常采用“函数指针+上下文指针”组合，或使用明确拥有生命周期的对象封装。

```cpp
using SampleHandler = void (*)(const Reading&, void*);
void deliver(const Reading& sample, SampleHandler callback, void* context) {
    if (callback != nullptr) callback(sample, context);
}
```

这只是接口示意：调用者必须保证 context 指向有效对象，并且回调只能按正确类型解释它。C++ lambda 可以捕获状态，但异步保存一个捕获局部引用的 lambda 仍可能悬空。回调在哪个任务或中断上下文执行决定了它能否等待、分配内存或访问共享状态，不能只看函数签名。

## 嵌入式 C++ 的实用取舍

优先使用明确大小的容器、简单值类型、受控所有权和短生命周期资源。虚函数、动态多态和复杂模板并非禁用，但引入它们应有具体需求；可观察的代码体积、内存与时序比“某种语法一定慢”的印象更可靠。框架可能关闭异常或 RTTI，不要假设桌面默认设置同样适用。

`volatile` 不是类的线程安全机制。一个对象即使所有数据成员都写成 volatile，多任务同时调用 `add()` 仍可能丢计数。可在外部使用互斥、让一个任务独占对象，或通过队列传递输入；选择取决于实时约束，后续 RTOS 章节再深入。

## 实验与练习

运行示例后输入 `reset`，计数、累计和、最小值与最大值应一起回到初态；随后一个样本到来，最小值和最大值都应等于该样本。观察这比在 main 中手工修改四个全局变量更容易保持一致。

练习：为什么不在全局对象构造函数里执行 `Wire.begin()`？答案：此时框架与相关系统状态可能尚未准备好，应在 `setup()` 调用显式初始化。为什么把对象放在静态区仍可能发生并发错误？答案：生命周期延长只解决是否存在，不解决访问同步。为什么“带析构函数”不自动等于正确 RAII？答案：还需正确所有权、拷贝/移动规则及匹配的释放操作。
